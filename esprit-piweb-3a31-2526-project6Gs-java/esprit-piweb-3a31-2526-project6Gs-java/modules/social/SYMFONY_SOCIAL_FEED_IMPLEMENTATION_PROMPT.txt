PROMPT START
============================================================

You are a senior Symfony developer. Build a complete Social Module Feed using Symfony + Twig (server-rendered), with full CRUD and interaction logic.

Goal:
Implement a production-ready social feed module (posts, comments, reactions, share, report, friends, notifications) in Symfony with Twig templates and Doctrine ORM.

Tech stack constraints:
- Symfony 6.4+ or 7.x
- Twig templates (no frontend SPA)
- Doctrine ORM + Doctrine Migrations
- MySQL/MariaDB compatible schema
- Symfony Security (authenticated users required)
- Use CSRF protection on all write actions
- Keep code clean, modular, and tested

Core Entities (Doctrine):
1) Post
- id (bigint)
- author (ManyToOne User, required)
- caption (text, required)
- mediaType (enum/string: NONE|IMAGE|VIDEO, default NONE)
- mediaPath (string nullable)
- thumbnailPath (string nullable)
- durationSeconds (int nullable)
- likesCount (int default 0)
- dislikesCount (int default 0)
- sharesCount (int default 0)
- commentsCount (int default 0)
- visibility (enum/string: PUBLIC|FRIENDS|PRIVATE, default PUBLIC)
- status (enum/string: ACTIVE|ARCHIVED|DELETED, default ACTIVE)
- createdAt, updatedAt

2) Comment
- id
- post (ManyToOne Post, required, on delete cascade)
- author (ManyToOne User, required)
- parentComment (ManyToOne Comment nullable, on delete cascade)
- body (text required)
- status (enum/string: ACTIVE|HIDDEN|DELETED, default ACTIVE)
- createdAt

3) Notification
- id
- recipient (ManyToOne User, required)
- actor (ManyToOne User, required)
- type (string, examples below)
- post (ManyToOne Post nullable)
- comment (ManyToOne Comment nullable)
- message (string nullable)
- isRead (bool default false)
- createdAt

4) FriendRequest
- id
- sender (ManyToOne User, required)
- receiver (ManyToOne User, required)
- status (PENDING|ACCEPTED|DECLINED|CANCELLED, default PENDING)
- createdAt

5) Friendship
- id
- user1 (ManyToOne User, required)
- user2 (ManyToOne User, required)
- createdAt
- unique(user1,user2)

6) PostReaction
- post (ManyToOne Post, PK part)
- user (ManyToOne User, PK part)
- reaction (LIKE|DISLIKE)
- composite unique/post+user

7) CommentReaction
- comment (ManyToOne Comment, PK part)
- user (ManyToOne User, PK part)
- reaction (LIKE|DISLIKE)
- composite unique/comment+user

8) PostShare
- post (ManyToOne Post, PK part)
- user (ManyToOne User, PK part)
- createdAt
- composite unique/post+user

9) PostReport
- id
- post (ManyToOne Post, required)
- reporterUser (ManyToOne User, required)
- reason (varchar nullable)
- createdAt
- unique(post, reporterUser)

External existing tables/entities expected:
- User entity/table already exists and has at least:
  id, firstName, lastName, email, profileImagePath

Business Rules to implement:
1) Feed visibility filter
- Show only ACTIVE posts.
- Viewer can see:
  - PUBLIC posts
  - PRIVATE posts only if viewer == author
  - FRIENDS posts only if viewer == author or viewer is friend with author

2) Post reactions
- Toggle LIKE/DISLIKE exactly as:
  - no prior reaction + click LIKE => add LIKE, likesCount +1
  - no prior reaction + click DISLIKE => add DISLIKE, dislikesCount +1
  - prior LIKE + click LIKE => remove reaction, likesCount -1 (not below 0)
  - prior DISLIKE + click DISLIKE => remove reaction, dislikesCount -1 (not below 0)
  - switch LIKE <-> DISLIKE updates both counters correctly

3) Comment reactions
- Same toggle logic as post reactions.
- Counters derived from comment reactions table or maintained consistently.

4) Shares
- Toggle share per user/post.
- Insert/delete in post_share.
- Update sharesCount accordingly (never below 0).

5) Reports
- One report per user per post.
- Duplicate report should return a safe message, no crash.

6) Comments
- CRUD for comments with nested replies.
- Only comment author or post author can edit/delete a comment.
- Deleting a comment removes its descendant replies.
- Keep post.commentsCount synchronized.

7) Post CRUD permissions
- Create: authenticated user only.
- Edit/Delete: only post author.
- Delete post also deletes related comments/reactions/shares/reports via cascades/services.

8) Friend flow
- Send request (prevent self-request, duplicates, or already friends)
- Accept request: create Friendship pair (normalized min user id in user1 / max in user2)
- Decline request
- Remove friend
- List friends
- List incoming requests
- Search users by name/email excluding current user

9) Notifications
- Create notifications for:
  POST_LIKE, POST_DISLIKE, POST_COMMENT, POST_SHARE, POST_REPORT,
  COMMENT_LIKE, COMMENT_DISLIKE, COMMENT_REPLY,
  FRIEND_REQUEST_SENT, FRIEND_REQUEST_ACCEPTED, FRIEND_REQUEST_DECLINED, FRIEND_REMOVED
- Do not notify self-actions.
- Unread counter endpoint + mark one read + mark all read.

10) Search in feed
- Filter by author display name or caption text.

11) Media handling
- Allow post with optional media upload:
  image types: jpg/jpeg/png/gif/webp
  video types: mp4/mov/m4v
- Store uploaded file path in mediaPath.
- Keep mediaType consistent.

Required Controllers (or equivalent):

If something is ambiguous, choose conventions that keep compatibility with this specification and clearly note assumptions in comments/README.
